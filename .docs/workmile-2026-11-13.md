### 2. 明确终态与取消语义

- 正常状态路径为 Created → Running → WaitingForModel → Completed / Failed。
- Delivered 且回复保存成功才映射为 Completed；不保证答案事实正确。
- 截断、未知、拒绝、过滤和不支持工具映射为 Failed，保留已有文本及明确原因。
- 模型、Context 或历史保存失败不会自动重试。
- Cancelling 表示请求取消；执行实际停止后才确认 Cancelled。
- 依赖超时不是业务取消，映射为 Failed。
- 取消一次查询或结果等待，不会取消已经接受的任务；任务使用独立取消源。
- 已有终态不会被迟到的取消或完成覆盖，旧任务不能释放后续任务的 Session 占用。
- Host 退出时停止接受，请求取消并等待收尾；超出退出期限显式失败，不伪装成已停止。

### 3. 对话中的可见变化

```text
You> 你好
Task accepted: <TaskId>. Use /wait or /task to view the result.

You> /wait
Task: <TaskId> [Completed]
Assistant> ...
```

| 命令 | 功能 |
|---|---|
| `/tasks [游标]` | 查看当前会话任务，默认最近 20 条，可向更早记录翻页。 |
| `/task [TaskId]` | 查询状态、版本和已有结果。 |
| `/wait [TaskId]` | 等待任务终态并展示回答或错误。 |
| `/cancel [TaskId]` | 请求取消，不保证返回时执行已经停止。 |

后三个命令省略 ID 时操作最近提交的任务；切换会话不会改变该 ID。
`/wait` 期间不读取新命令；不等待时可以查询或请求取消。
同会话的上一任务尚未结束时，新提交和关闭明确拒绝；不同会话可并行。
原有会话、历史命令继续保留，命令不作为聊天内容发送给模型。

## 架构认识与当前边界

- Session、History、Task、取消、存储和日志属于传统软件工程；LLM 模块是外部推理服务适配。
- Agent 的关键差异是让模型在受控边界内提出下一步行动，程序校验、执行并回传事实。
- 当前仍是具备任务管理和多轮历史的 LLM 应用底座，没有工具行动闭环。
- 本地 Runtime 可以直接访问 Ollama 或云端模型入口，不必为了接入 MCP 先建设自己的服务端。
- 薄客户端方案可将 Runtime、历史和 Context 放到服务端，但操作用户本机仍需上传资料或授权的本地工具桥接。
- 服务端管理历史只减少客户端重传，不自动减少进入模型的上下文。
- 仍为可信本地单用户、内存存储；没有登录、远程授权、持久化、恢复、任务排队或容量治理。
- 不支持等待用户、补充输入或暂停恢复；ProvideInput 明确拒绝。
- 没有提交 RequestId 幂等协议；任务完成后的相同输入是新任务。
- 没有工具、ReAct、流式回答、自动摘要或长期记忆；字符预算尚不是精确 Token 预算。
