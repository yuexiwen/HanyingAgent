## 今天完成了什么

### 1. 明确执行结果协议

- 新增 [ExecutionOutcome / ExecutionConclusion](../HanyingAgent/SRC/Contracts/Execution/Execution.md)，不再将 ModelResponse 直接当作整个执行的结果。
- [DirectExecutor](../HanyingAgent/SRC/Runtime/Execution/DirectExecutor.cs) 统一解释正常交付、截断、未知、拒绝、过滤和不支持的动作。
- 仅 Stop、有效文本、无工具请求时判定 Delivered；合法响应中的工具请求优先判定为不支持。
- 非法响应明确报错，依赖失败、超时和主动取消继续通过异常传播，不自动重试。
- 保留文本、用量和模型结束元数据；Console 只依据执行结论展示，不重复判断模型协议。
- 执行结论不是 Task 状态；Delivered 只表示符合策略交付规则，不保证答案事实正确。
- 未引入执行器基类、策略工厂、ReAct 或另一套任务生命周期状态。

### 2. 稳定日志事件编号

- [LogEvents](../HanyingAgent/SRC/Diagnostics/LogEvents.cs) 集中定义编号与事件名。
- 1000 段用于执行，2000 段用于 Context / 历史窗口，3000 段用于模型调用，4000 段用于对话协调及会话命令。
- 区分 EventId（事件类型）、Category（来源）、ExecutionId（一次执行）和 SessionId（所属会话）。
- 正常交付使用 Information，非正常交付使用 Warning，已知执行失败使用 Error。
- 保留隐私边界：默认不记录输入、系统指令、历史正文或完整回复。

### 3. 本地用户与会话

- 新增[用户管理与本地身份上下文](../HanyingAgent/SRC/Runtime/Users/Users.md)，创建实际本地用户资料，并保证并发初始化只创建一次。
- 新增[会话管理](../HanyingAgent/SRC/Runtime/Sessions/Sessions.md)，支持创建、查询、列举和关闭。
- 按已保存 UserId 检查归属，知道其他会话 ID 不等于获得访问权。
- 启动时创建 Default 会话；同一进程内可创建多个独立会话。
- 执行期间使用临时 lease，拒绝同会话重复执行或关闭；失败和取消也释放。
- 不伪造正式 TaskId / Active 状态；本期保护是进程内执行互斥，不是完整任务管理。

### 4. Conversation 与内存存储

- [LocalConversationManager](../HanyingAgent/SRC/Runtime/Conversation/LocalConversationManager.cs) 实现纯文本历史追加、查询和分页。
- [InMemoryDialogueStore](../HanyingAgent/SRC/Infrastructure/Persistence/InMemoryDialogueStore.cs) 通过三个内部端口保存用户、会话和消息。
- 在锁内完成消息幂等检查与会话内 Sequence 分配，不依赖时间戳区分先后。
- 相同 MessageId、归属和内容的重试返回原记录；改变载荷明确冲突。
- 默认读取最近 20 条，页内升序，游标读取更早消息；分页大小限制为 1–200，游标绑定 Session。
- 读取返回独立快照；Assistant 记录保留实际结束原因，不把截断或未知输出伪装成完整回答。
- Closed 会话保留历史可读，拒绝新追加；已有相同记录的幂等重试仍可返回。

### 5. 有界历史窗口

- 新增 [ConversationWindow](../HanyingAgent/SRC/Runtime/Context/ConversationWindow.cs)，在 Context Builder 之前选择并转换历史。
- 默认最多携带最近 10 个正常完成的 User / Assistant 片段，受总输入字符预算约束。
- 从近到远选择，最终正序发送；预算不足时停止纳入更早完整片段，不截断当前输入。
- 系统指令与当前输入本身超限就明确失败，Builder 保留最终校验。
- 最多扫描 200 条旧记录，防止连续失败时无限翻页。
- 截断、未知、拒绝、过滤及未回答的旧输入保留在记录中，但不进入后续模型历史。
- 淘汰的是本轮 Context，不删除 Conversation；重要信息离开窗口后仍可能忘记。

### 6. 对话协调与 Console

- [DialogueCoordinator](../HanyingAgent/SRC/Runtime/Conversation/DialogueCoordinator.cs) 串联输入保存、历史选择、执行与回复保存。
- 当前 User 先记录，再通过 Sequence 选择历史，确保当前输入只进入请求一次。
- 模型失败或取消保留已提交的 User，不伪造成功回复。
- 回复保存失败标注 SaveAssistant 阶段，不自动再次调用模型；消息幂等不等于模型调用幂等。
- 不支持的工具动作不伪装成普通文本历史，记录明确事件；本期不支持工具历史和非空 TaskId 关联。
- [ConsoleApplication](../HanyingAgent/SRC/Host/ConsoleApplication.cs) 新增 `/new 名称`、`/sessions`、`/use 完整ID`、`/history [游标]`、`/close`，保留 `/exit` 和 Ctrl+C。
- 命令不调用模型；空历史明确提示。关闭会话后须新建或选择会话再提问。
- DI 注册管理器、Store、窗口和协调组件，Runtime 通过 DialogueRequest 接收参数，不依赖 Host 配置类型。

## 当前边界

- 可信本地单用户模式，没有登录、角色或多用户远程授权。
- 用户、Session、Conversation 都只保存在内存中，退出进程即丢失。
- 只有 Direct 单次模型策略，没有工具执行、联网检索、ReAct 或流式输出。
- 没有正式 Task 提交、后台运行、状态查询、业务取消、等待用户或恢复机制。
- Console 不自动读写 WorkingMemory；Conversation 历史与语义记忆仍是不同能力。
- 字符预算不是 Token 预算，不能保证装入模型窗口，也没有精确输出空间预留。
- 没有自动摘要、语义提取、相关性召回、滚动日志文件或 OpenTelemetry。

## 后续计划

### 优先：最小 Task / Orchestration 闭环

1. 核对已有 ITaskManager、TaskInfo、TaskStatus、TaskResult，不另建重复状态机。
2. 在编排层需要统一调用执行器时提取最小 IExecutor，不引入没有实际复用需求的抽象基类。
3. 提交任务先返回接受快照，后台继续运行；提供状态与终态结果查询。
4. 原子协调任务创建和 Session 占用，同一会话最多一个未结束任务。
5. 把当前对话保存与历史选择流程接入任务执行，不在 Host 或 TaskManager 中复制一套。
6. 明确 ExecutionOutcome 到任务终态的政策，尤其是截断、未知、拒绝和过滤；不把 Delivered 当事实正确证明。
7. 区分取消一次查询 / 等待与取消业务任务；实际停止后再确认 Cancelled，并释放会话。
8. 日志关联 TaskId、SessionId、ExecutionId；验证失败、取消、重复提交和关闭竞态下不会留下占用。

先完成 Direct 策略的正常、失败和取消收尾；等待用户、恢复、排队、Skills 与其他执行策略不同时扩张。
当前临时 turn lease 需与正式任务占用整合，不能并存两套互相矛盾的运行状态。
