# HanyingAgent Workmile - 2026-11-11

## 今日里程碑

**从可独立测试的基础组件，推进到可以在本地终端实际使用的单轮问答闭环。**

```text
Console 输入
  → DirectExecutor
  → LocalContextBuilder
  → OllamaLanguageModelRuntime
  → 本地 Ollama / qwen2.5:1.5b
  → Console 展示回复与结束状态
```

工作记忆、Context Builder 和 Ollama 适配器是已有基础；今天主要完成本地环境准备、应用接线、关联日志和中文输入修复。
这条调用链已经可用，但还不是具有会话管理、任务编排和工具循环的完整 Agent。

## 今天完成了什么

### 1. 本地模型环境与真实联调

- 安装 Ollama 0.40.16，下载 qwen2.5:1.5b，模型文件约 986 MB。
- 验证本地 API `http://127.0.0.1:11434` 可用。
- 先组合真实 Context 与模型适配器，再通过实际 Console 完成模型调用，不只依赖 HTTP 替身测试。
- 合成问题 `2 + 3` 返回 `5`，结束原因为 Stop。

### 2. Generic Host、DI 和配置

- [Program.cs](../HanyingAgent/Program.cs) 负责启动、停止 Host 和运行 Console。
- [ApplicationHost](../HanyingAgent/SRC/Host/ApplicationHost.cs) 集中注册依赖、Options、HTTP 客户端和日志。
- 内存 Store、工作记忆 Manager 与无状态 Context Builder 使用 Singleton。
- 每轮输入创建独立 DI Scope，解析瞬态执行器与模型适配器，避免单例直接捕获类型化客户端。
- [appsettings.json](../HanyingAgent/appsettings.json) 配置模型地址、名称、上下文窗口、超时、系统指令、字符上限、输出 Token 上限、Temperature 和日志级别。
- 启动时校验配置，支持环境变量与命令行覆盖；配置随构建、发布复制到输出目录。

### 3. 单次执行与 Console

- 新增 [DirectExecutor](../HanyingAgent/SRC/Runtime/Execution/DirectExecutor.cs)，通过契约串联 Context 与一次模型调用。
- 原样保留模型文本、结束原因和用量，不把一次模型响应等同于业务 Task 完成。
- 新增 [ConsoleApplication](../HanyingAgent/SRC/Host/ConsoleApplication.cs)，支持连续输入独立问题。
- 支持空白输入跳过、`/exit`、EOF，以及 Ctrl+C 取消当前等待并退出。
- 已知调用失败、超时会明确提示并允许继续输入，不自动重试。
- 截断、拒绝、过滤、工具调用或未知结束原因明确展示，不伪装成完整回答。

### 4. 结构化日志

- 使用标准 `ILogger<T>`，未另造 Logger 包装或全局单例。
- 每次执行生成 ExecutionId，执行器、Context 和模型日志自动共享 Scope。
- 记录阶段开始、消息数、记忆数、字符数、模型名称、结束原因、Token 用量与耗时。
- 区分失败、主动取消和超时；已知异常只在执行边界记录一次。
- 日志写入 stderr，交互与回答写入 stdout；默认不记录输入、记忆正文或完整回复。
- 当前没有正式 TaskId / SessionId，不将 ExecutionId 冒充业务任务标识。

### 5. 中文输入编码修复

现象：Agent 对中文问题回复“不理解”，而 Ollama 命令行能够正常回答。

- 排查发现本机默认输入代码页为 ibm437。
- 本地 HTTP 捕获证明，UTF-8 中文输入经过原 Console 入口后可能成为乱码。
- 另将中文按该代码页转换，复现出与用户反馈完全相同的英文道歉，输入 Token 数同为 25。
- 在创建 Host、捕获 Console.In / Console.Out 之前，将输入和输出统一为无 BOM 的 UTF-8。
- 新增真实子进程测试，逐字验证中文到达 HTTP 请求，并验证中文及非 BMP 字符回复没有损坏。
- 修复后原问题能够得到正常中文回答，真实调用输入 Token 数为 29。

此问题通过修正输入链路解决，没有通过修改模型或提示词掩盖。
管道发送端仍需提供 UTF-8 字节；已经被发送端替换成问号的内容无法由接收端恢复。

## 当前边界与架构认识

- 当前是连续单轮问答，每轮只有系统指令和本轮输入，不保存或自动加载历史。
- 工作记忆已注册，但 Console 传入空 MemoryOwners，不自动读写记忆。
- 尚无正式 Session / Task 实现，Orchestration 仍是设计骨架。
- 尚无工具执行、联网检索、ReAct、流式输出或持久化；模型生成链接不代表实际联网核实。
- 字符上限不是 Token 预算，没有自动裁剪或输出空间预留。
- 当前日志仅输出到 Console，尚无滚动文件、指标或 OpenTelemetry。
- Execution 是模块名称，不是基类；DirectExecutor 是独立的 sealed class，当前没有统一执行器接口。
- Orchestration 管理任务接受、启动、等待、取消与收尾；Executor 管任务内部的执行步骤，二者不互相替代。

## 下一步计划

以下为建议顺序，不代表对应功能已经实现或接口设计已经定稿。

### 第一阶段：明确执行协议

- 区分一次 ModelResponse 与整个执行的结果，明确结束、失败、取消及等待用户的表达。
- 核对已有 Task 契约，避免创建另一套语义重复、状态矛盾的协议。
- 在 Orchestration 需要统一调用执行器时提取最小 IExecutor；不为继承而新增抽象基类。
- DirectExecutor 保留单次模型调用策略，暂不预建策略工厂和 ReAct 框架。

### 第二阶段：会话与对话历史

- 实现最小本地 Session、Conversation 管理，按现有契约维护归属、消息顺序和幂等追加。
- 为多轮对话选择并转换历史，不把完整历史不加限制地传给模型。
- 将当前用户输入记录一次，避免从历史和本轮请求重复加入。
- 验收同一会话能够承接上文，不同会话不会串历史；身份与授权不因知道 ID 而自动成立。

### 第三阶段：最小 Orchestration

- 实现任务提交、后台执行、查询、结果保存和收尾；接受快照不等待最终模型回答。
- 协调 Task 创建与 Session 占用，同一会话最多一个未结束任务。
- 区分调用等待取消与业务任务取消，确保失败、取消后释放会话。
- 在可信执行上下文中关联 TaskId、SessionId 与 ExecutionId，扩展现有日志链路。
- 先验证 Direct 策略的完整生命周期，不同时扩展排队、恢复、Skills 和多执行策略。

### 后续再推进

- 精确输入 Token 预算与历史裁剪。
- 一个受控工具，以及有步数、超时和取消约束的 ReAct。
- 持久化、工作记忆自动写入、日志文件与可视化追踪。
