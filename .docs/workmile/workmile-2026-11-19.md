### 3. 接入 /remember 用户记忆

在 [ConsoleCommandHandler](../../HanyingAgent/SRC/Host/Console/ConsoleCommandHandler.cs)
增加命令：

```text
/remember 解释代码时优先使用 C++ 类比
```

当前行为：

- 将明确输入保存为当前可信用户的 User 级 WorkingMemory。
- 复用已有 IWorkingMemoryManager 和内存 Store，不另建一套记忆存储。
- 无须选中 Session，不创建业务 Task，不写入 Conversation，也不调用模型。
- 空白内容拒绝；写入失败或取消不显示成功。
- 使用 Preference 类型，Source 为 `console:/remember`，Confidence 为 1、Importance 为 0.5。
  这些是本命令提供的元数据，不是模型评分；Confidence 不代表内容已被验证为事实。
- 不设置默认到期时间；当前也没有自动分类、去重更新或自动敏感内容识别。
- 纯文本帮助和富终端帮助均补充命令、进程内有效范围与敏感信息提示。

用途限定为非敏感编码偏好和技术约定，不应输入个人信息、密钥或其他敏感内容。
当前没有新增记忆查看、修改或遗忘命令；底层已有相应操作，但 Console 管理入口仍待后续设计。

### 4. 让用户记忆进入实际模型上下文

后续对话自动读取同一用户最近最多 20 条有效工作记忆：

- 通过 LocalUserContext 获取可信 UserId，不从模型输出推导记忆访问范围。
- 仅读取该 User Owner，不自动扩大到其他用户、Session、Task 或 Global。
- 有效状态和到期过滤沿用 WorkingMemory Manager 的既有规则。
- 编排器校验读取结果非空且归属一致，异常、取消或跨归属结果显式失败。
- 记忆在同一进程内跨 Session 可用，不因切换会话而丢失。
- 这是按更新时间读取近期记忆，不是依据当前问题进行向量或语义检索。

最终输入结构为：

```text
System：系统指令 + 存在记忆时的参考资料使用规则
User：记忆参考数据，采用带标题的 JSON
User / Assistant：选中的历史消息
User：当前输入
```

记忆正文不提升为系统指令，参考消息不追加到 Conversation。
没有记忆时不插入空参考块，也不额外修改系统指令。
JSON 格式和使用规则不构成模型绝不会服从恶意参考文本的保证。

### 5. 将编排调用扁平化

今天接入记忆时，最初沿用旧结构：

```text
Orchestrator
    → Executor
        → ContextBuilder
            → Memory
```

这种结构隐藏了准备阶段，同时历史由编排器协调、记忆却由 Builder 读取，阅读边界不一致。
最终改为由同一个编排层显式组织平级能力：

```text
DialogueOrchestrator
    → Conversation：保存用户输入
    → ConversationWindow：读取并选择历史
    → WorkingMemoryManager：读取当前用户记忆
    → ContextBuilder：构造 ModelInvocation
    → DirectExecutor：调用模型并解释响应
    → Conversation：保存 Assistant 回复
```

对应调整：

| 组件 | 最终职责 |
|---|---|
| [DialogueOrchestrator](../../HanyingAgent/SRC/Runtime/Orchestration/DialogueOrchestrator.cs) | 协调数据读取、上下文构造、执行和回复保存。 |
| [BuildContextRequest](../../HanyingAgent/SRC/Contracts/Context/Operations/Requests/BuildContextRequest.cs) | MemoryOwners 替换为明确的 MemoryItem 列表 Memories。 |
| [LocalContextBuilder](../../HanyingAgent/SRC/Runtime/Context/LocalContextBuilder.cs) | 接收已有数据，校验、去重排序、格式组装和校验总长度，不再依赖 Memory 服务。 |
| [DirectExecutor](../../HanyingAgent/SRC/Runtime/Execution/DirectExecutor.cs) | 接收已构造的 ModelInvocation，调用一次模型并解释结果，不再依赖 ContextBuilder。 |
| [ApplicationHost](../../HanyingAgent/SRC/Host/ApplicationHost.cs) | 同步新的构造依赖和 DI 组合。 |

MemoryOwners 的移除是请求协议变更，调用方和 JSON 测试已同步修改。
旧 JSON 只有 MemoryOwners 而缺少必需的 Memories 时明确失败，不悄悄按空记忆处理。

扁平化针对模块协调边界，不是把所有 Store 和 Provider 的内部调用都搬到 Orchestrator。
模块仍封装自己的实现细节，没有新增转发层、策略工厂或通用协调框架。

### 6. 明确阶段状态与日志关联

- WaitingForModel 改为在 Context 构造成功后、进入 Executor 前更新。
- 记忆读取或 Context 构造失败时，不调用模型，也不提前标记为等待模型。
- ReadMemory、BuildContext 和 WaitForModel 的已知异常由编排边界记录阶段，再原样向上传播。
- Execute 阶段仍由执行器记录相关异常，避免编排层重复记录。
- Context 构造现在发生在 Executor 的 ExecutionId 范围之前，使用外层 SessionId、
  以及任务入口已有的 TaskId 关联；Executor 与模型日志额外携带 ExecutionId。
- 记忆读取和 Context 构造后检查取消，避免依赖忽略取消、正常返回后继续进入模型。

在扁平编排基础上，进一步提取：


以及回复保存失败不重试模型等行为保持不变。

## 学习与设计讨论

### 业务任务和后台执行的边界

- CreateTask 登记 TaskInfo、建立任务和会话索引、占用 Session，本身不启动 Agent。
- 共享 Gate 保护“检查空闲、创建任务、绑定会话”整组操作，不只是保护单个字段。
- TransitionTask 校验预期状态，不覆盖已进入 Cancelling 的任务。
- TaskInfo 是可查询的业务快照，ExecutionHandle 是本进程的执行控制资源，二者通过 TaskId 关联。
- 控制链和后台执行链可以 await 同一个取消回调 Task；等待不会重复执行回调。
- User / Session / Task 是记忆归属范围，不等于长期 / 短期，也不等于持久化方式。

### 单 Agent 优先

讨论了 Agent 定义、独立执行上下文、多 Agent 分工与上层协作的可能建模。
当前决定仍是完善唯一 Agent，不引入 Agent、AgentRun 或多 Agent 调度对象。
这些讨论不表示项目已经实现了相应类型或能力。

### 自动提取与记忆整合尚未实现

当前机制是：

> 手动记住，自动读取。

普通输入只进入 Conversation，不自动变成 Memory。
后续需要分别设计：

1. **Conversation 到候选记忆**：识别值得保留的结论、技术约束或编码偏好，
   区分讨论中的方案与已确认决策，保留来源，明确适用范围。
2. **候选审核与写入**：检查重复、更新和冲突；可先采用自动建议、用户确认，
   不让模型自行决定访问范围或直接写入权威记忆。
3. **短期到长期整合**：按稳定性、复用价值和可信证据筛选、合并，不是简单复制或延长到期时间。
4. **更新和遗忘**：定义信息失效、旧结论被替代以及到期后清理的规则。
5. **失败策略**：记忆处理失败是否影响主任务需要明确，不应因此重新调用已经完成的主模型请求。

以上是讨论方向，没有新增自动提取、用户确认流程或长期记忆实现。

## 当前限制与下一步

1. 记忆不持久化，跨 Session 不等于跨进程；退出后 User Memory 也会丢失。
2. 最近最多 20 条是数量选择，不是按问题相关性召回；更早记忆可能仍在存储中但不进入本次上下文。
3. 历史窗口尚未预留记忆预算，总字符限制包含参考规则、JSON 元数据及转义开销。
   加入记忆后超限会明确失败，不静默丢弃记忆或截断当前输入；后续需统一预算策略。
4. /remember 没有自动内容分类、重复合并或敏感信息检测，也尚无 Console 查看和遗忘命令。
5. Task / Session 记忆未自动接入，任务或会话结束不会自动让对应记忆失效或删除。
6. 长期记忆、自动提取、整合、确认、冲突处理和清理策略仍需先设计再实现。
7. 继续沿单 Agent 主线完善，不提前加入多 Agent、继承模板或通用工作流框架。
