## 一、Skill、Prompt 与 Tool 的区别

| 模块 | 定位 | 本期提供的能力 |
|---|---|---|
| Skill | 描述某类任务应该如何处理的方法、步骤和注意事项。 | 管理本地文件，列举名称与描述，按名称取得完整方法说明。 |
| Prompt | 可复用的提示模板，本次特指本地模板，不是 MCP Prompts。 | 列举名称、描述和参数，将参数填入模板生成文本。 |
| Tool | 真正执行操作的能力。 | 本次没有修改工具执行协议或 Agent 接入方式。 |

Skill 和 Prompt 是两个独立模块，实现 Skill 不需要先实现 Prompt。
Skill 正文最终可能成为模型提示的一部分，不代表它必须依赖 Prompt 模板管理模块。
两者可以在未来协作，但不强制一个 Skill 对应一个 Prompt，也不强制互相引用。

Skill 中的方法说明通常由 LLM 理解，不由程序逐句翻译成函数调用。
如果需要不可跳过的步骤、固定顺序和确定的失败处理，应另建工作流或状态机。
加载 Skill 不表示步骤已执行，也不表示获得了工具权限。

## 二、公共契约

公共协议只包含名称、描述、正文和参数等数据，不暴露文件路径或文件流。
未来可以通过新的实现替换为远程调用，而不要求调用方理解本地文件系统。

### Skill

[ISkillManager](../../HanyingAgent/SRC/Contracts/Agent/Capabilities/Skills/Operations/ISkillManager.cs)：

```csharp
Task<IReadOnlyList<SkillDefinition>> ListDefinitionsAsync(
    CancellationToken cancellationToken);

Task<SkillDocument> LoadAsync(
    string skillName, CancellationToken cancellationToken);
```

- [SkillDefinition](../../HanyingAgent/SRC/Contracts/Agent/Capabilities/Skills/Models/SkillDefinition.cs)：Name、Description。
- [SkillDocument](../../HanyingAgent/SRC/Contracts/Agent/Capabilities/Skills/Models/SkillDocument.cs)：Definition、Instructions。
- 列举只返回元数据；按名称加载才向调用方返回完整正文。

### Prompt

本次确认选择参数化模板方案，而不是仅按名称读取固定文本。
[IPromptManager](../../HanyingAgent/SRC/Contracts/Agent/Capabilities/Prompts/Operations/IPromptManager.cs)：

```csharp
Task<IReadOnlyList<PromptDefinition>> ListDefinitionsAsync(
    CancellationToken cancellationToken);

Task<RenderedPrompt> RenderAsync(
    string promptName,
    IReadOnlyDictionary<string, string> arguments,
    CancellationToken cancellationToken);
```

- [PromptDefinition](../../HanyingAgent/SRC/Contracts/Agent/Capabilities/Prompts/Models/PromptDefinition.cs)：Name、Description、Arguments。
- [PromptArgumentDefinition](../../HanyingAgent/SRC/Contracts/Agent/Capabilities/Prompts/Models/PromptArgumentDefinition.cs)：参数 Name、Description。
- [RenderedPrompt](../../HanyingAgent/SRC/Contracts/Agent/Capabilities/Prompts/Models/RenderedPrompt.cs)：Name、Content。
- 本期所有参数均为必填字符串，不支持默认值或可选参数。
- 无参数的固定模板可以传空字典渲染，不额外增加 LoadAsync。

两个模块的 ListDefinitionsAsync 都按名称 Ordinal 排序，返回只读列表。
未知名称、非法输入、取消和初始化错误明确传播，不返回成功形状的替代结果。

## 三、文件组织与格式

```text
Skills
└─ document-analysis
   └─ SKILL.md

Prompts
└─ translate
   └─ PROMPT.md
```

只扫描配置根目录的直属子目录，不递归扫描。
每个直属子目录必须包含对应文件，目录名与元数据 name 必须按 Ordinal 完全一致。

### Skill 示例

```markdown
---
name: document-analysis
description: 分析文档，核对证据并整理结论。
---

# 文档分析

1. 明确分析目标。
2. 阅读相关文档。
3. 区分事实和推断。
4. 输出结论和来源。
```

元数据只允许 name、description，正文必须非空。
参考通用 Agent Skills 的文件组织，本期仅支持该子集，不宣称完整兼容。
不加载参考文件，也不执行脚本。

### Prompt 示例

```markdown
---
name: translate
description: 将文本翻译成指定语言。
arguments:
  - name: language
    description: 输出语言。
  - name: text
    description: 待翻译文本。
---
请将以下文本翻译成 {{language}}：

{{text}}
```

元数据仅支持 name、description、arguments。
arguments 可省略或为 `[]`；每项仅支持非空的 name、description。

共享格式约束：

- 文件为严格 UTF-8，允许 BOM、LF 和 CRLF。
- YAML front matter 以独立的 `---` 行开始和结束。
- 使用 YamlDotNet 16.3.0 解析，不手写按冒号拆分的解析器。
- Skill 和 Prompt 名称长度为 1–64，只含小写 ASCII 字母、数字和连字符；
  连字符不能位于首尾或连续出现。
- YAML 非法、重复字段、不支持的字段、空正文、缺失文件或重复名称均明确失败。

## 四、配置、初始化与快照

[appsettings.json](../../HanyingAgent/appsettings.json) 新增：

```json
{
  "Skills": {
    "Directory": null,
    "MaxFileBytes": 65536,
    "MaxSkillCount": 100
  },
  "Prompts": {
    "Directory": null,
    "MaxFileBytes": 65536,
    "MaxPromptCount": 100,
    "MaxOutputCharacters": 65536
  }
}
```

Directory 为 null 表示没有来源，初始化后返回空列表。
空白目录配置非法；指定不存在或不可读的目录会导致启动失败，不退化为空列表。
相对路径基于 Host ContentRootPath（默认应用输出目录），不依赖启动终端的当前目录。
文件不自动复制到构建输出，应部署到配置目录或配置其绝对路径。

[ApplicationHost](../../HanyingAgent/SRC/Host/ApplicationHost.cs) 注册两个 Manager 为单例，
分别通过私有嵌套的 SkillInitializationService、PromptInitializationService 在启动时异步初始化。
SkillInitializationService 最初为独立文件，按讨论移入 ApplicationHost，
与已有 ToolRegistrationValidator 保持一致；它只负责转发初始化调用，不包含文件业务逻辑。

```text
绑定配置 → 异步扫描与读取 → 校验所有文档 → 一次发布只读快照
```

- 不在构造函数里同步等待文件 I/O。
- 用 SemaphoreSlim 协调初始化，成功后重复初始化不重新加载。
- 用 FrozenDictionary 发布完整索引，失败或取消不发布部分目录。
- 初始化前访问接口明确失败。
- 运行时通过快照查询或渲染，不重新读取磁盘。
- 文件修改在重启后生效，不提供热更新或运行时注册、修改、删除接口。

## 五、Prompt 参数校验与渲染

[LocalPromptManager](../../HanyingAgent/SRC/Runtime/Agent/Capabilities/Prompts/LocalPromptManager.cs)
仅支持精确的 `{{name}}` 占位符。
参数名为 1–64 个字符，以小写 ASCII 字母开头，后续允许小写字母、数字和下划线。
名称与参数名均区分大小写。

启动校验：

- 每个占位符必须有参数声明。
- 每个声明参数必须在正文中使用。
- 允许同一参数出现多次。
- 不支持占位符内空格、表达式、条件、循环、模板包含或双花括号转义语法。

运行时校验与渲染：

```text
查找模板 → 复制参数字典 → 校验参数集合 → 单次字面值替换 → 返回结果
```

拒绝缺失、额外参数或 null 值，允许空字符串。
参数值中的 `{{language}}`、`$1` 或换行都作为普通文本插入，不递归渲染。
并发调用使用各自的参数快照和 StringBuilder，不共享单次请求状态。

MaxOutputCharacters 限制最终文本的 UTF-16 字符单元数量，不是 Token 或字节数。
重复替换逐次计入，每次追加前检查，避免先分配巨大结果再拒绝；超限报错，不截断。
单文件字节限制和模板数量限制也有明确阈值，等于阈值允许，超过则拒绝。

## 六、Task.FromResult 与异步接口

[LocalSkillManager.LoadAsync](../../HanyingAgent/SRC/Runtime/Agent/Capabilities/Skills/LocalSkillManager.cs)
当前是同步的内存查询：

```csharp
return Task.FromResult(document);
```

这表示创建一个已经成功完成、结果为 document 的 Task。
它不启动线程，不把查字典变成后台操作，也不要求前面必须调用异步方法。

保留 Task 返回类型是公共契约的选择，方便未来改成远程服务等真正需要等待的实现。
当前调用方 await 时可直接取到结果，无需挂起；未来若 Task 未完成才需要等待。
Prompt 的发现与渲染也采用同样方式；真正的异步文件读取发生在初始化阶段。

因此，应区分：

- 方法返回 Task，不代表执行过程一定发生异步等待。
- 方法使用 async / await，是编写可等待流程的语言机制。
- 当前没有实际等待的实现，不需要为了命名带 Async 而人为增加后台任务。

## 七、磁盘加载与模型上下文加载

本次明确指出：**当前不是正文的磁盘惰性加载，而是启动时完整快照。**

```text
InitializeAsync：读取全部元数据和正文并缓存
LoadAsync：按名称获取已加载文档
```

选择完整快照的原因是提前发现错误、固定运行期版本、简化并发和文件变更行为。
默认最多 100 个 Skill、每个文件最多 64 KiB，原始文件总量上限约 6.25 MiB；
这不等于进程实际内存占用，解码和解析还会有额外开销。

未来若改成首次加载正文时才读取文件，需要重新设计并发加载、失败缓存、
文件版本变化和错误发现时机，不能继续承诺启动时已校验所有正文。

模型侧的预期流程则是另一个问题：

```text
提供全部可用 Skill 的名称和描述
    → LLM 选择并提出结构化加载请求
    → Agent 加载选中的完整正文
    → Context 组装
    → LLM 分析下一步
```

正文按需进入模型上下文，不要求磁盘也必须按需读取。
上述模型侧流程尚未接入；Prompt 也不必把全部目录交给 LLM，可以由用户或程序显式选择。

LLM 后续若需要操作，应返回结构化工具调用，由 Agent 校验并执行，
不是把普通 answer 文本当成命令。工具结果回传模型后，再决定继续操作或输出最终回答。

## 八、GeneratedRegex 与 partial 方法

PromptManager 使用三个生成式正则方法：

| 方法 | 用途 |
|---|---|
| NamePattern | 校验 Prompt 名称。 |
| ArgumentPattern | 校验参数名称。 |
| PlaceholderPattern | 查找 `{{name}}` 并提取参数名。 |

```csharp
[GeneratedRegex(@"正则规则", RegexOptions.CultureInvariant)]
private static partial Regex NamePattern();
```

这里不是没有实现，而是 GeneratedRegex 源代码生成器在编译时提供实现。
partial 允许声明和实现分开，生成代码返回缓存的正则对象，不是每次调用都重新构造。
带显式可访问性和返回值的这些 partial 方法，如果真的没有生成实现，会编译失败。

讨论中 VS Code 曾显示 CS8795，提示缺少 partial 方法实现。
实际 Release 构建成功，随后编辑器诊断也显示无错误，
因此观察结果符合设计时分析或诊断刷新滞后的情况，未修改正则实现。
若再次出现，可保存文件并重新加载 VS Code 窗口，再对照实际构建结果确认。

## 九、信任边界与当前限制

- 只加载可信部署的 Skill 和 Prompt。配置目录不是模型可以任意指定的读取入口。
- 查询按名称查索引，不把调用方名称直接拼成文件路径。
- 根目录及祖先路径、子目录和文件不能包含符号链接、目录联接或其他 ReparsePoint。
  该检查不是抵御恶意并发替换文件系统的沙箱。
- Skill 正文是说明，不执行其引用的脚本，不自动授予工具权限。
- Prompt 渲染输出普通文本，不决定模型消息角色，不自动成为 System 指令。
- 用户参数不会因插入可信模板而变得可信；字面值替换不等于提示注入防护。
- Context 信任层级、预算及正文放置方式由后续接入另行设计。
- 不主动记录完整正文和参数值；解析器异常可能携带出错位置或文本片段。
- 本次没有实现自动 Skill 选择、参考资料加载、Prompt 表达式或模型执行循环。
